- XorShift32 の右シフトが論理になっているかの未検証
  - なぜ問題か: int を使った算術右シフトでも seed=1 の前半数列は偶然一致し得るため、誤実装が検出不能
  - どう直すか: MSB が立つ状態を作るシード（例: 0x80000000u）や十分回した後の値で期待列を検証する

- SevenBag の j 計算で符号付きにキャストしていないかの未検証
  - なぜ問題か: (int)に先にキャストすると負値→負インデックスや分岐の死に枝が起きても seed=1 では露呈しない
  - どう直すか: Next() が 2^31 以上を返すケースで j が [0..i] に入ることを検証（uint での剰余を強制）

- SevenBag が乱数を「ちょうど6回」消費する保証の弱さ
  - なぜ問題か: 5回や7回消費でも偶然同じ並びが出ると検査が通り得る（同語反復）
  - どう直すか: Generate() 呼出し後の rng.Next() が「7番目の期待値」になることを明示的に検証する

- SevenBag が毎回「新しい配列」を返す保証の未検証
  - なぜ問題か: 内部静的配列の使い回しでも短期の内容比較だけでは緑になる（張りぼて）
  - どう直すか: 返り値同士の ReferenceEquals が常に false、および一方を書き換えても他方が変わらないことを検証

- MinoShape に未定義 MinoType を渡した際の例外未検証
  - なぜ問題か: 想定外の列挙値が将来入り得るのに ArgumentOutOfRangeException を投げない実装が温存される
  - どう直すか: (MinoType)999 等で SpawnCells が ArgumentOutOfRangeException を投げることを検証

- GameState.Tick(int) の異常系（0、負値、int.MinValue）の未検証
  - なぜ問題か: -ticks などの実装で int.MinValue が回り込み、意図せず Tick が進む経路が「見てないのに緑」になる
  - どう直すか: ticks=0, -1, int.MinValue でいずれも外から読める状態が一切変わらないことを検証

- 初回以降の Tick の増分（LP-04）の未検証
  - なぜ問題か: 初回に 0 へリセットまでは確認できても、2回目以降に +1 されない張りぼて実装が温存される
  - どう直すか: 初回 Tick 後にさらに Tick() して TickCount==1 になることを検証

- 入力 API（Move/Rotate/SoftDrop）が状態を変えず乱数を消費しないことの未検証
  - なぜ問題か: 隠れた副作用や RNG 消費があっても現在の受入範囲では検出されない（見ていないのに緑）
  - どう直すか: Ready/Playing それぞれで多数回呼んでも公開状態不変、初回出現時の 7-Bag が影響を受けないことを検証

- NextQueue の公開が「外から書けない」だけでなく内部リストを露出していないかの未検証
  - なぜ問題か: ReadOnly ラッパー越しでも内部共有だと将来の内部変更が外部観測に漏れる
  - どう直すか: 取得直後の参照と後続内部操作で別オブジェクトになる（コピー返却）か、少なくとも外部から Add 等不能を検証

  - なぜ問題か: 出現時に盤面へ書き込む実装が潜んでも、現受入では検知できない（仕様乖離が温存）
  - どう直すか: 盤面 API が公開されていれば全マス空であることを検証。非公開なら可視化用アクセサを追加して検査可能化を検討
