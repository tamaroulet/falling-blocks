- RNG/時間APIの禁止が機械検査で不十分
  - 何が: forbidden_patterns が UnityEngine.Random と引数なし new Random() のみ。new Random(1)、Random.Shared、System.Random 明示参照、DateTime.Now、Stopwatch、Environment.TickCount、Thread.Sleep/Task.Delay は素通り
  - なぜ問題か: この単位では乱数を一切生成しない契約をすり抜け可能。「見ていないのに緑」になる
  - どう直すか: 禁止パターンを網羅（System.Random、Random.Shared、DateTime.Now 等）するか、静的解析で API 参照を検出。確認: grep と CI でアセンブリ参照をチェック

- Board.IsOccupied のオーバーフロー経路未抑止
  - 何が: int.MinValue/int.MaxValue を渡されても「オーバーフローしない」要件だが、実装が y*Width+x 等の一次元化を境界判定前に行うと桁あふれ
  - なぜ問題か: 係数や分岐が結果に影響（中間値で回り込み）し、外側では true を返すべき箇所で例外/誤判定
  - どう直すか: 常に境界判定を先行し、算術を行わない（x,y の比較のみ）。確認: int.Min/Max/±1 で IsOccupied を直接叩くテストを追加

- InBounds/IsVisibleRow/IsBufferRow の負値・極値の境界テスト不足
  - 何が: y<0、y==Height、y==int.Min/Max、x 同様のケースが明示的に受入条件に無い
  - なぜ問題か: 0/Width/Height 周辺だけ緑で、極値で落ちる「見ていないのに緑」
  - どう直すか: 各 API へ負値/上限/極値入力のテストを追加。IsVisibleRow/IsBufferRow は範囲外で必ず false を検証

- Board 占有状態の実体未保持でも初期テストが通るリスク
  - 何が: 現段階では盤面は常に空のため、IsOccupied を「盤面内は常に false、外は true」で張りぼて実装しても通過しうる
  - なぜ問題か: 後続単位での拡張時に破綻。仕様「インスタンスごとに持つ」を満たさない
  - どう直すか: インスタンスフィールドの存在を反射で検査、または将来の変更を見越しセル配列の存在をテストに固定。確認: 非 public フィールドの型/静的でないことを検査

- Board の占有配列を static にしても検知しない可能性
  - 何が: 「static 共有禁止」は記述のみで、複数 Board 間の独立性をテストが直接検証していない恐れ
  - なぜ問題か: 複数ゲーム/テスト間の汚染で非決定化
  - どう直すか: 2 インスタンスで内部配列参照が異なることを反射で検査。確認: ReferenceEquals が false であることを検証

- NextQueue の公開が実質可変になりうる
  - 何が: IReadOnlyList で List を直接返すと、外部が List にダウンキャストして改変可能
  - なぜ問題か: 「外から書き換えられない」契約違反なのに見えづらい
  - どう直すか: Array.Empty<MinoType>() か ReadOnlyCollection を返す、または defensive copy。確認: (obj as List<MinoType>) が null であることをテスト

- InjectSeed の Ready 以外での呼び出し挙動が曖昧
  - 何が: 「Ready のときだけ有効」だが、非 Ready の場合に例外か無視か未規定
  - なぜ問題か: 実装差異が混入しやすい（仕様とテストの乖離）
  - どう直すか: 仕様に明記（例外を投げる/無視する）。確認: CoreContractTests に明示的な期待挙動を追加

- InjectSeed の内部保持が検証不能
  - 何が: 「内部に保持するだけで公開しない」ため、実装が何も保持しなくてもテストで検出困難
  - なぜ問題か: 後続の乱数利用単位で非決定や回帰を招く
  - どう直すか: 内部フィールドの存在を反射で確認、または次単位での一貫性テストに依存。確認: private uint フィールドの有無をチェック

- Height と Visible/Buffer の整合チェックの欠如
