指摘1: Board.cs.meta が最小構成で MonoImporter ブロックが欠落している可能性
- 何が: fileFormatVersion と guid しかなく、通常ある MonoImporter（serializedVersion, defaultReferences, executionOrder 等）が見当たらない
- なぜ問題か: Unity のバージョンや環境差で暗黙デフォルトが埋まり差分発生・実行順序やデフォルト参照が意図せず変化するリスク。将来のリファクタ時にメタで固定されていない設定が失われやすい
- どう直すか: Unity エディタで該当ファイルを一度 Reimport し、生成された完全な .meta をコミット。差分が出るか確認。必要なら [DefaultExecutionOrder] をコード側に付けてメタ依存を減らす

指摘2: GUID の一意性・整合性の未確認
- 何が: 45814ff3c46320f49943f5f9895cffc5 の重複や他アセットとの衝突確認が文書から不明
- なぜ問題か: GUID 重複はインポート時のアセット解決を壊し、シーン/Prefab で Missing Script が発生
- どう直すか: リポジトリ全体で GUID の重複をスキャン（grep/rg で '*.meta' を対象に重複検出）。Unity エディタで AssetDatabase.GUIDToAssetPath を使う簡易ツールでも可

指摘3: シーン/Prefab 側の m_Script 参照の整合性未確認
- 何が: 既存シーン・Prefab がこの GUID に依存しているかの追跡がない
- なぜ問題か: GUID 変更や欠落時に Missing Script が潜在化し、実行時に破綻しても CI が見逃す恐れ
- どう直すか: リポジトリで m_Script: {fileID: 11500000, guid: 45814ff3c46320f49943f5f9895cffc5 を検索し、参照点を把握。CI で MissingMonoBehaviour 検出ジョブを追加

指摘4: OS レベル操作による GUID 変化への対策が運用頼みの可能性
- 何が: ファイル移動/改名を Unity 以外で行うと .meta が再生成され GUID が変わる
- なぜ問題か: 参照切断（Missing Script）を招くが、レビューで気づきにくい
- どう直すか: Unity の Version Control 設定を「Visible Meta Files/Force Text」に統一し、pre-commit で「.cs と .meta の整合」「新規 .cs に .meta 無しを拒否」を自動検査

指摘5: asmdef 境界変更時の破壊経路の検査不足
- 何が: スクリプトの配置変更でビルド対象アセンブリが変わる際の型解決検証が不明
- なぜ問題か: GUID は同じでも型が見つからない状態やコンパイル順依存の不具合が出る
- どう直すか: 影響範囲のシーン/Prefabを開いてドメインリロードで警告/エラーが出ないか確認。CI で batchmode 起動時の Editor.log をパースし Missing/TypeLoad を失敗にする

指摘6: 実行順序やデフォルト参照がメタに依存しているかの可観測性欠如
- 何が: MonoImporter 不在だと executionOrder/defaultReferences が暗黙の 0/空になる

- どう直すか: 実行順序は [DefaultExecutionOrder] を用いてコードで固定。デフォルト参照は [SerializeField] + 初期化コードに寄せ、シリアライズ初期値に依存しない

指摘7: 「見ていないのに緑」を招く CI の盲点
