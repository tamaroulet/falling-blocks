- Phase が常に Ready 固定で状態遷移不能
  - なぜ問題か: InjectSeed の条件 if (Phase == Ready) が常に真となり、分岐が意味を持たない。同語反復で否定経路（非 Ready）がテスト不能。
  - どう直すか: Phase を private set + 明示的な状態遷移 API を実装。少なくともテスト用に内部コンストラクタ/ファクトリで任意 Phase を作れるようにし、分岐の両側を実行可能にする。

- InjectSeed の効果が外部から観測不能（_seed 未使用・未公開）
  - なぜ問題か: 張りぼて検査になりやすく、呼び出しても成功/失敗や補正結果を検証できない。「見ていないのに緑」を誘発。
  - どう直すか: 少なくとも戻り値（bool か補正後 seed）を返すか、readonly の Seed プロパティ（internal + InternalsVisibleTo）を追加。あわせて RNG/NextQueue などに実効果を紐付け、テストで観測可能にする。

- Phase ≠ Ready 時の挙動が設計上存在せず、否定経路のテストが組めない
  - なぜ問題か: 「Ready 状態でのみ有効」という仕様が検証不能。死んだ分岐はカバレッジに乗らず、誤実装の温床。
  - どう直すか: 上記の状態遷移 API を用意し、非 Ready での InjectSeed を例外/false/NoOp のいずれかで明示。テストで非 Ready を作って否定経路を必ず通す。

- NextQueue が Array.Empty に固定で更新不可
  - なぜ問題か: 仕様（キューが供給される）と乖離。常に長さ 0 のため、仕様通りの動作や seed 依存の再現性を検証できない。
  - どう直すか: private List<MinoType> を保持して外部には ReadOnlyCollection を返す設計に変更し、生成/消費 API を用意。テストで長さ変化と内容を検証。

- ActiveMino が常に null のまま更新手段がない
  - なぜ問題か: 「Ready では null」という仕様は満たすが、以降の遷移や配置検証が不可能で張りぼて化。
  - どう直すか: スポーン/固定などの API を実装し、内部フィールドに反映。テストで Ready→Active の遷移と不変条件を機械判定。

- InjectSeed が無効時に黙殺（戻り値/例外なし）
  - なぜ問題か: 呼び出し側が失敗を検知できず、終了コードや例外非発生のみで「成功」と見なす誤判定が起こりうる。
  - どう直すか: 例外を投げるか、TryInjectSeed(out uint applied) のように結果を返す契約に変更。テストで成功/失敗両方をアサート。

- seed の境界値（0/1/uint.MaxValue）検証ができない
  - なぜ問題か: 0→1 補正や最大値の取り扱いが仕様だが、観測点がないためテストで確認不能。
  - どう直すか: 補正後の seed を返す/公開する。テストで 0→1、1→1、uint.Max→uint.Max を明示確認。フェールケースも網羅。

- IReadOnlyList に配列（Array.Empty）の実体を露出
  - なぜ問題か: 将来非空配列を返す設計にすると、呼出側が配列にキャストして改変できる（IReadOnlyList は防御にならない）。
  - どう直すか: 内部は List を保持し、外部は ReadOnlyCollection か IReadOnlyList ラッパーを返す。配列は返さない。テストで外部改変が反映されないことを確認。

- カウンタ（Score/LinesCleared/TickCount）の桁あふれ検証の足場がない
  - なぜ問題か: いずれも int だが加算 API がなく、境界値/中間値での回り込みバグをテストできない。将来実装時に同種の見落としリスク。
  - どう直すか: 加算 API を用意し checked/unchecked の方針を仕様化。int.Max 近傍や中間計算のオーバーフローを網羅するテストを先に用意。

- 隔離が慣習レベル
  - なぜ問題か: 「Ready のときのみ〜」等がコメント/無効分岐頼みで、機構として強制できていない。
  - どう直すか: 不変条件をコードで強制（状態機械/契約/例外）。テストで破壊的呼び出しが拒否されることを検証。
