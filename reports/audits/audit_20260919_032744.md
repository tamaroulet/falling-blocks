- 何が: Height が 22 に手書きされ、VisibleHeight + BufferHeight と一致することがコードで保証されていない
  - なぜ問題か: 値の不整合が起きてもコンパイルは通り、IsBufferRow/InBounds/配列サイズが食い違う隠れバグになる
  - どう直すか: public static readonly int Height = VisibleHeight + BufferHeight にし、静的初期化時に Debug.Assert で整合性を検査。単体テストで同値も検証

- 何が: IsOccupied が盤外を常に true として扱うポリシーを埋め込んでいる
  - なぜ問題か: 境界計算のオフバイワンや x/y 取り違えが「常に詰まる」動作に見え、原因切り分けが困難（張りぼて化・同語反復の温床）
  - どう直すか: Out-of-bounds と Occupied を区別できる API（例: TryGetOccupied(out bool occupied) or GetCellState で列挙型返す）を用意。テストは「盤外」と「占有」を分けて期待値を定義

- 何が: public const（Width/VisibleHeight/BufferHeight/Height）を跨 asmdef で参照する場合のインライン化リスク
  - なぜ問題か: 依存アセンブリが再ビルドされないと古い値が残り、実装と参照側で寸法が食い違う（Unity 固有の破壊経路）
  - どう直すか: public static readonly に変更してインライン化を避ける。依存関係を asmdef で明示し、値変更時に依存側が確実に再ビルドされることをCIで検証

- 何が: 配列の次元順が [x, y]（列, 行）であることが暗黙
  - なぜ問題か: 呼び出し側が [row, col] と誤解しても型で検出できず、IsOccupied の「盤外=占有」方針と相まって不具合が潜る
  - どう直すか: 内部配列への直接アクセスを一元化（Get/SetOccupancy(x,y) 以外で触れない）。引数名の明示と呼び出し側レビュー。テストで x/y 入替え時に破綻する性質検査を追加

- 何が: 可視行・バッファ行の区分に関する不変条件がコード/テストで検査されていない
  - なぜ問題か: 「見ていないのに緑」。Height の不整合や境界の排他性が崩れても成功扱いになる
  - どう直すか: テストで以下を機械判定: Height==VisibleHeight+BufferHeight、任意の y に対し IsVisibleRow(y) と IsBufferRow(y) は互いに排他、かつ InBounds(0,y) のとき必ずどちらかが真
