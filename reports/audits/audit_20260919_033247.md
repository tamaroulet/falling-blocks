- 何が: MonoImporter セクションが見当たらない（guid と fileFormatVersion のみ）
  なぜ問題か: Unity が自動補完し環境差で内容が変わる。実行順序やデフォルト参照の意図が落ち、毎回差分が出る
  どう直すか: 同一 Editor で当該 .cs を Reimport して生成される MonoImporter ブロックごとコミット。CIで再インポート差分ゼロを検証

- 何が: GUID の唯一性・固定性に対する検査/運用の記述がない
  なぜ問題か: メタのコピーや競合解決で GUID 重複/再発行が起きると参照が崩壊する
  どう直すか: CIで全 *.meta の guid を走査し重複検出。pre-commitで *.meta の直接複製を禁止。Unity Editorで GUID→AssetPath 辞書を検査

- 何が: .cs と .meta の原子的な移動/改名の保証がない
  なぜ問題か: 片方のみ移動/改名で meta 再生成→GUID 変化→シーン/Prefab が Missing Script 化
  どう直すか: VCS の move を必須化し .meta 同時移動をチェック。CIで全シーン/Prefabを開き Missing Script を検出

- 何が: asmdef 変更やアセンブリ境界越え時の検査がない
  なぜ問題か: GUID が同じでもアセンブリ名変更で型解決失敗し Missing になる
  どう直すか: asmdef 変更のPRで、Headlessで全シーン/PrefabをロードしTypeLoadException/Missing Scriptをログ検出

- 何が: Script Execution Order の明示がない（executionOrder が meta に存在しない）
  なぜ問題か: 順序依存の初期化が暗黙になると環境差で不安定化
  どう直すか: 必要な順序を「スクリプト実行順序」で指定し meta に反映。CIで想定 order を lint

- 何が: シリアライズ済みフィールド改名への移行規約が見えない
  なぜ問題か: GameState は状態保持が想定され、改名でデータ喪失が発生
  どう直すか: FormerlySerializedAs の使用を規約化。YAML 強制再シリアライズ後の差分で欠落検出

- 何が: Editor バージョン固定の記述がない
  なぜ問題か: Unity 版差で .meta の serializedVersion/書式が変わりノイズや破壊が出る
  どう直すか: ProjectVersion.txt をCIで固定し、異なる版で生成された meta を拒否。EditorImage を統一

- 何が: 「見ていないのに緑」のリスク（存在/終了コードのみで合格）
  なぜ問題か: meta が2行でもテストを素通りし、実際には Unity が再生成する欠落を見逃す
  どう直すか: CIで *.cs.meta に MonoImporter/serializedVersion の必須キーを正規表現で検証。Unity再インポート後にgit差分が無いことを必須化
